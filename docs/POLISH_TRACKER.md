## 2. How to resume (checklist for a fresh session)

```
cd /home/user/fuzzy-journey && git status -sb && git log --oneline | head -5      # branch claude/ecstatic-gauss-f495v8
export XDG_DATA_HOME=/tmp/xdg_m
/opt/godot/Godot_v4.4.1-stable_linux.x86_64 --headless --path godot --import       # after any new class_name file
tools/test_ui.sh                       # UI suite under xvfb (~35 min in the sandbox, run alone). Ends with "UI PASS"
tools/test_all.sh                      # headless suites (engine, sim, net)
godot/tests/title_shots.gd             # -- <out> <w> <h> <save|nosave> [lang]   title stills   (TB_TS=1.5 for text size)
tools/title_dive.sh [out] [flat|globe] [off|light|full]                            # records the Continue dive (mp4 + gif)
node docs/ui_variants/build.mjs && node docs/ui_variants/shoot_popups.mjs /tmp/pb/pop   # pop-up mock-ups
```
Pitfalls learnt:
* `/tmp/xdg_m/settings.cfg` is written by tests (the overflow test leaves **text_scale 1.5** and a language behind): a screenshot script must set `cfg["text_scale"] = 1.0` itself (title_shots does).
* A scratch `tests/_*.gd` must never be committed (check `git status` before every commit).
* `pkill -f <pattern>` can kill your own shell; do not use it. Long jobs: run in the background and poll with short bounded loops (`for i in $(seq 1 55); do ... sleep 2; done`).
* Lambdas that capture nodes freed later (`_clear_overlay` frees the title) print "Lambda capture ... was freed": read the node from a member variable inside the lambda and guard with `is_instance_valid`.
* A push can race a background push of the same branch (`cannot lock ref`): check `git rev-parse HEAD origin/<branch>` after a push that printed an error.
* `TB_NOANIM=1` makes `TBKit.motion_ok()` false (tests that need still pictures); `TB_NOANIM=` (empty) enables animation.

### Phone map looked like a picture (owner question: "why is the mobile interface not the same as the desktop ... looks like a png")
* **Cause**: the map shader renders into a buffer that is a fraction of the control's LOGICAL size (low 0.6, medium 0.85, high 1.0). On a desktop the logical stage is about the window's pixels, so that is fine. On a phone the stage is 390 units tall while the screen has 1000+ physical pixels, so the map got a third of the screen's resolution and was stretched: blocky stair-stepped coasts, borders a few pixels thick, no fine province lines. It was the same on the globe and the flat map. The interface chrome (crest, gauges, rail, dial, tuner) is drawn as vectors / text at the real resolution and was always sharp, which made the contrast with the blocky map worse.
* **Fix**: `TBMapView._rs()`: the buffer scale now follows the physical pixels per logical unit (window size / logical size), capped by a per-tier pixel budget (`PX_BUDGET` low 0.7 MP, medium 1.4 MP, high 2.4 MP), and never below the tier's old fraction. A desktop (logical >= physical, or already over the budget) gets **exactly** the old scale, so desktop pictures and cost are unchanged; only phones / HiDPI screens gain sharpness. Strokes stay the same logical width (the shader's `px_scale`). Used for the buffer size, the shader's radius / flat scale / `px_scale`, partial redraw rectangles and the redraw cache key. "Copy diagnostics" now prints `map_scale` and `map_buffer`.
* **Check**: pictures `docs/screens/phone_map/before_after.png` (844x390 phone, medium tier; left before, right after, top globe, bottom flat) and `phone_globe_after.png` / `phone_flat_after.png`; `tests/hud_view.gd` takes `TQ=low|medium|high`; partial redraw equals full redraw at the phone scale (`tests/map_partial.gd -- 1688 780 6` with `TB_UI_SCALE=2`).
* **Phone vs desktop chrome, by design** (the Bezel demo's own phone layout, a 390-unit stage): the rail is a straight column of icons without labels (desktop: arc with a ruler and labels), smaller medallions and gauges with captions, no nation name beside the crest, one notice row, four lenses plus a "..." button in the tuner, zoom buttons beside End Turn, a smaller minimap without caption. Same parts, same look, less text. Globe and flat have the same chrome; only the map, the minimap's content and which markers show differ.

### Why the test runs abort at exit (audit)
* **Symptom**: scripted tests (`-s tests/x.gd`) with `--rendering-driver opengl3` end with `corrupted size vs. prev_size` / `corrupted double-linked list` and exit code 134, after printing their result. The real game exits with 0.
* **Findings**: (1) separate, now fixed: "Lambda capture at index 0 was freed" (a lambda that captures a node logs this if the node is freed first, even with an `is_instance_valid` guard inside): `main.gd` dissolve and toast timers now connect `node.queue_free` directly, the `panel.gd` close tween is bound to its node, `ui_kit.gd` modal focus restore captures a `WeakRef`. (2) The abort: a minimal script reproduces it: `var x: TBHud = null` in the `-s` script plus loading `main.tscn`, two frames, `quit()`. Without the typed reference it does not abort, nor with `TBGame` / `TBWorld` (plain data classes), nor with `--headless`. A typed reference to `TBHud`, `TBMapView`, `TBMinimap`, `TBFx` or `TBPanel` does abort. Under valgrind (`tests/t5.gd`, `LP_NUM_THREADS=0`) the run finishes and reports invalid reads / writes in `pthread_mutex_lock` / `unlock` on a mutex inside a 1936 byte block that the engine's shutdown code had already freed, plus an invalid free of a 48 byte block, all called from shutdown inside the engine (the binary is stripped, so no names). No game code appears in any trace.
* **Reading**: an engine shutdown ordering bug in Godot 4.4.1 (script / resource teardown), triggered when the main-loop script statically depends on UI scripts; not memory corruption from our GDScript. Our code is not involved, the shipped game is not affected, and the exit code of a test run is not meaningful until this is worked around.
