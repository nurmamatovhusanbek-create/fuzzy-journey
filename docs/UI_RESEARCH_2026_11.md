# UI research, November 2026: what strategy games teach, and what we do with it

Scope: the interface of Terra Bellum on a desktop (Android runs the same layout). Method: read what designers say they did and what players say went wrong in grand strategy, 4X and management games; audit our own screens at 1920 x 1080 and 1280 x 800 against that and against `docs/UI_STANDARD.md`, `ui_tokens.gd` and `docs/ARCHITECTURE.md`; change only inside the tokens and the layering. Most sources are developer diaries, reviews and forum threads: anecdote, not usability studies, and said so where it matters. I could not open full pages (no fetch tool in this session), so quotes are from search excerpts; the diary links are the place to read more.

## 2. General findings

* **Progressive disclosure has a limit.** Keep depth to two or three levels; hiding essential information is the known risk ([Nielsen Norman Group](https://uxtigers.com/post/progressive-disclosure), [UI patterns](https://ui-patterns.com/patterns/ProgressiveDisclosure)). Tooltips are for *why*, not the only copy of anything critical ([tooltip guidelines](https://uxplanet.org/tooltip-guidelines-best-practices-and-common-mistakes-with-examples-bde5993048f0): short, delayed and faded in, anchored, with a touch path).
* **Legibility is a setting and a default.** Contrast at least 4.5:1 for text, 3:1 for large text, 7:1 for a high-contrast mode; text size chosen by the player; a text list as an alternative to the map ([Unity](https://unity.com/blog/video-game-accessibility-basics), [Xbox guidelines](https://devdocs.xbox.com/gaming/accessibility/xbox-accessibility-guidelines/101)). A 28 px minimum at 1080p is quoted for living-room play from secondary sources; I could not confirm it in the official page, so it is not used here.
* **Information tiers by contrast.** Primary data in the highest contrast, secondary subdued; the same formatting for hundreds of numbers is the strategy-game failure ([article](https://mygamedesign-frontend.pages.dev/how-do-you-communicate-complex-systems-through-visual-design); unsourced claims in it are ignored).
* **Windows and the map.** The map is the playfield: panels that talk about a place should show it (highlight on hover, a lens that comes and goes with the panel) and should not hide it.
* **Scaling.** 4K and ultrawide are where UIs go blurry or oversized; a UI size setting is expected.

## 3. Our screens against this (audit, 1920 x 1080, 1280 x 800)

What already matches: a consistent window frame (title, subtitle, ruler, body, footer); tiles that summarise and rows that detail (Nations, Budget); alerts that jump to the map; a contextual End Turn with a loose-ends card once per turn that can be switched off; a lens bar; breakdown tooltips that say why; a UI size and a text size setting.

What did not:

1. **The type scale existed on paper only.** `ui_tokens.gd` says caption 12, detail 13, body 14, figure 16, "absolute floor at 100 %", but nothing read those roles and the UI layer scaled the stage so that 1 unit was 0.8 to 0.9 pixel: at 1080p 71 of the 192 texts on the main screens were 10 px or smaller (captions 8.5, section headings 9.5 to 10, button labels 10). The research above says legibility is the first complaint on dense strategy UIs.
2. **Council:** the same minister heading repeated for each matter, no severity, a ratio shown as "942.0x".
3. **Raise troops bar:** the text column was 118 units wide, so a sentence broke into four lines ("against" alone on a line).
4. **Nations list:** long names trimmed with an ellipsis (a tooltip carries the full name).
5. **No link between a panel and the map** beyond "Show on map" buttons (Victoria 3 and the Humankind complaints point both ways: highlight, but do not cover).

## 4. Decisions

* **D1 Type floor and interface size.** `TBTokens.FS_FLOOR = 10.5` units is the smallest text anywhere (`K.fs`, `K.fsf`). The stage divisor per interface size became a token (`UI_STAGE_K`: compact 1.0 = the old normal, normal 0.84, large 0.72), so a 1080p screen gets 14 px body and 11.5 px captions by default. Measured by `tests/ui_type_floor.gd` (fails below 11 px at 1080p).
* **D2 Hierarchy of a window:** title and subtitle, summary tiles, rows (name, one line of effect, control), footer. Section headings are captions; severity and state use the status tokens only (`neg`, `warn`, `pos`, `info`), never a new colour.
* **D3 Council as ministers:** one heading per minister with the number of matters; one row per matter with a severity bar; the gravest minister first.
* **D4 Space:** text columns next to a slider get a width from content, not a fixed small number.
* **D5 Not done on purpose:** nested tooltips (a term-by-term tooltip system is a big feature with the "misleading or useless" risk; our breakdown tooltips already cover the numbers that matter), a second table of every nation (the Nations list already sorts), a Stellaris-style outliner rewrite (ours exists: F7).

## 5. Next cycles (each ends with screenshots and the suite)

1. Map linkage: hovering a nation in the Nations list and a row in the Outliner highlights it on the map without opening anything over it.
2. Settings: an "auto" interface size that reads the display (1080p, 1440p, 4K) and a one-time prompt when the screen is large.
3. Tile and card pattern: Realm, Nations and Budget use the same summary tile component (one height, one label role).
4. Tests: `ui_type_floor` at 1280 x 800, 1920 x 1080 and 2560 x 1440 in every language; the council grouping; the raise bar width.
5. `docs/UI_STANDARD.md` updated with the type roles, the sizes and the hierarchy rules above.
